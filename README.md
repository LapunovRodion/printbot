# PrintBot — Telegram-бот печати документов

Принимает от сотрудников файлы **DOCX** и **PDF**, спрашивает принтер, режим сторон и число копий,
после подтверждения печатает на офисном принтере. Работает на компьютере с Windows.

Спецификация, план и приёмочные сценарии — в `specs/001-telegram-print-bot/`.

## Возможности

- Печать DOCX и PDF по одному сценарию: файл → принтер → стороны → копии → подтверждение
- Несколько принтеров с признаком доступности; двусторонняя печать предлагается только там, где она есть
- Доступ по общему коду офиса, блокировка после 5 неверных попыток на 15 минут
- Последовательная очередь на каждый принтер — страницы разных документов не перемешиваются
- Понятные причины отказа: принтер выключен, нет бумаги, замятие, нет тонера, файл защищён паролем
- Бессрочный журнал заданий для администратора, смена кода и отзыв доступа прямо из бота
- Файлы пользователей удаляются с диска сразу после печати

## Требования к хосту

| Компонент | Зачем |
|---|---|
| Windows 10/11 x64 | принтеры подключены под учётной записью пользователя |
| Python 3.11+ | сам бот |
| [LibreOffice](https://www.libreoffice.org/) | конвертация DOCX → PDF |
| [SumatraPDF](https://www.sumatrapdfreader.org/) (portable) в `tools\SumatraPDF.exe` | печать PDF с дуплексом и копиями |
| Токен от [@BotFather](https://t.me/BotFather) | доступ к Telegram |

## Быстрая установка (рекомендуется)

Скачайте и распакуйте проект, затем в PowerShell в его папке выполните:

```powershell
powershell -ExecutionPolicy Bypass -File setup.ps1
```

Скрипт сам проверит Python и LibreOffice, скачает SumatraPDF, создаст окружение,
спросит токен бота и принтеры, запишет `.env` и `printers.toml` и предложит
настроить автозапуск. Запускать можно повторно — уже настроенное он не трогает.

| Ключ | Зачем |
|---|---|
| `-Reconfigure` | переспросить токен и принтеры заново |
| `-SkipTests` | не запускать тесты после установки |
| `-ShowOutput` | показывать полный вывод pip и pytest, а не только итог по шагам |

Ход установки пишется в `logs\setup.log`. Смотреть его прямо во время работы можно
из второго окна PowerShell:

```powershell
Get-Content logs\setup.log -Wait -Tail 30
```

Токен бота в лог не попадает: на время его ввода запись приостанавливается.

Останется только запустить бота и записать код доступа из консоли:

```powershell
.venv\Scripts\python -m printbot
```

## Установка вручную

```powershell
python -m venv .venv
.venv\Scripts\pip install -e ".[dev]"
copy .env.example .env
copy printers.example.toml printers.toml
```

1. В `.env` заполните `BOT_TOKEN` и `ADMIN_IDS` (свой Telegram ID можно узнать у @userinfobot).
2. Узнайте точные имена принтеров и впишите их в `printers.toml`:

   ```powershell
   .venv\Scripts\python tools\list_printers.py
   ```

3. Запустите:

   ```powershell
   .venv\Scripts\python -m printbot
   ```

При первом запуске бот один раз напечатает в консоли сгенерированный **код доступа** — сохраните его
и раздайте сотрудникам. Дальше код меняется командой `/setcode` в боте; в базе хранится только его хеш.

Полные настройки — `specs/001-telegram-print-bot/contracts/configuration.md`.

## Автозапуск

Бот должен работать **в сессии пользователя**, под которым подключены принтеры: служба под
`LOCAL SYSTEM` сетевых принтеров не видит.

```powershell
schtasks /Create /TN "PrintBot" /TR "C:\printbot\.venv\Scripts\pythonw.exe -m printbot" /SC ONLOGON /RL LIMITED /F
```

Затем в Планировщике заданий у задачи `PrintBot` включите «Перезапускать при сбое» (каждую 1 минуту,
до 3 раз) и снимите «Останавливать при переходе на батарею». Отключите спящий режим компьютера.

## Команды бота

| Команда | Кто | Что делает |
|---|---|---|
| `/start`, `/help` | все | приветствие и краткая инструкция |
| `/cancel` | пользователи | отменить оформляемое задание |
| `/status` | пользователи | последние 5 своих заданий |
| `/printers` | пользователи | список принтеров с доступностью |
| `/journal [N]` | админ | последние задания всех пользователей |
| `/setcode` | админ | сменить код доступа |
| `/revoke <id>`, `/users` | админ | отозвать доступ, список авторизованных |
| `/purge_journal CONFIRM` | админ | безвозвратно очистить журнал |

## Разработка

```powershell
.venv\Scripts\pytest -q          # весь набор тестов (принтер не нужен)
.venv\Scripts\ruff check src tests tools
```

Тесты работают на фейковых бэкендах печати и конвертации, поэтому проходят на любой ОС.
Реального хоста Windows требуют только `core/printing/windows.py` и `core/conversion/libreoffice.py` —
их проверяют приёмочные сценарии из `specs/001-telegram-print-bot/quickstart.md`.

## Логи

| Файл | Что внутри |
|---|---|
| `logs\setup.log` | ход установки, дописывается при каждом запуске `setup.ps1` |
| `logs\printbot.log` | работа бота: задания, ошибки печати, попытки входа |

Смотреть в реальном времени: `Get-Content logs\printbot.log -Wait -Tail 30`.
Файл ротируется по 5 МБ, хранятся 5 последних. Токен бота и код доступа в логи не пишутся.

## Известные особенности

- **Дуплекс**: трактовка длинной/короткой кромки различается у драйверов. Перед вводом в эксплуатацию
  проверьте двустороннюю печать на каждой модели (сценарий 6.2 в quickstart.md); при необходимости
  в `core/printing/windows.py` меняется флаг `duplexlong` → `duplexshort`.
- **Шрифты**: если шрифтов документа нет на хосте, LibreOffice подберёт замену и вёрстка может
  измениться. Установите на хост типовые офисные шрифты.
- **Прерванные задания** после перезапуска бота не перепечатываются автоматически: нельзя отличить
  «не напечаталось» от «напечаталось, но бот упал». Автор получает уведомление и решает сам.

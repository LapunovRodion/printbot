## R1. Фреймворк Telegram-бота

**Decision**: `aiogram 3.x` (long polling).

**Rationale**: Полностью асинхронный — цикл событий бота и воркеры печати живут в одном `asyncio`-приложении без потоков-костылей. Встроенный FSM (`StatesGroup` + `FSMContext`) точно ложится на диалог «файл → принтер → стороны → копии → подтверждение» (FR-006…FR-011). Middleware — естественное место для проверки доступа (FR-020), одна точка вместо проверки в каждом хендлере. Long polling не требует белого IP и проброса портов, что критично для офисного компьютера за NAT (FR-029). Актуальные версии — 3.25–3.27 (ветка `dev-3.x`), требуется Python 3.10+; ветка 4.x существует, но проект пинуется на 3.x как на широко документированную.

**Alternatives considered**:
- `python-telegram-bot` — зрелая, но `ConversationHandler` менее гибок при «пользователь прислал новый файл посреди диалога» (US1, сценарий 4), и интеграция с собственными фоновыми воркерами менее прямая.
- `telebot`/`pyTelegramBotAPI` — проще, но нет полноценного FSM и middleware, авторизацию пришлось бы дублировать в каждом хендлере.
- Webhook вместо polling — требует публичного адреса и TLS; для машины в офисе это лишняя инфраструктура.

**Ключевые API (подтверждено по документации)**: `Dispatcher`/`Router`, `StatesGroup`+`State`, `state.set_state/update_data/clear`, `bot.download_file(file_path, dest)`, `InlineKeyboardMarkup(inline_keyboard=[[InlineKeyboardButton(text=..., callback_data=...)]])`, `FSInputFile` для отправки файлов.

## R2. Конвертация DOCX → PDF на Windows

**Decision**: headless LibreOffice:
`soffice.exe --headless --norestore -env:UserInstallation=file:///<изолированный профиль задания> --convert-to pdf --outdir <job_dir> <file.docx>`

**Rationale**: Бесплатно и не требует лицензии MS Office на офисном компьютере. Работает неинтерактивно и без залогиненного Office. Отдельный `-env:UserInstallation` на каждый запуск снимает главную проблему LibreOffice — конфликт «уже запущенный экземпляр», из-за которого второй одновременный вызов молча завершается ничего не сделав. Результат — PDF, который одновременно даёт: (а) единый путь печати для DOCX и PDF, (б) достоверное число страниц до печати (FR: предупреждение об объёме).

**Alternatives considered**:
- **MS Word через COM** (`pywin32`, `docx2pdf`) — лучшая точность вёрстки, но требует установленного и лицензированного Word; в неинтерактивном режиме Word склонен зависать на модальных диалогах (повреждённый файл, отсутствующий шрифт), требует `pythoncom.CoInitialize()` в каждом потоке и не работает под учётной записью службы. Оставлен как опциональный второй `DocumentConverter` — интерфейс это позволяет без переписывания логики.
- Печать DOCX напрямую через `ShellExecute(..., "print", ...)` — параметры дуплекса и копий не передаются, печатает на принтере по умолчанию. Не подходит для FR-006/FR-007/FR-014.
- Чисто питоновские конвертеры (`docx2pdf` без Word, `python-docx` + рендер) — не воспроизводят вёрстку, риск не пройти SC-003.

**Риски**: несовпадение шрифтов на хосте меняет разбиение на страницы (зафиксировано как edge case). Митигация — установить типовые офисные шрифты на хост при развёртывании; таймаут конвертации 120 с с завершением процесса.

## R3. Печать PDF с выбором принтера, дуплекса и числа копий

**Decision**: SumatraPDF (portable) CLI:
`SumatraPDF.exe -print-to "<Имя принтера>" -print-settings "<duplexlong|duplexshort|simplex>,<N>x,paper=A4,monochrome" -silent -exit-when-done "<file.pdf>"`

**Rationale**: Единственный лёгкий инструмент, который одной командой закрывает сразу все требуемые параметры: конкретный принтер (FR-014), режим сторон (FR-006), число копий (FR-007). Portable-сборка кладётся рядом с ботом — не требует установки и прав администратора. Код возврата и `-silent` дают машинно-проверяемый результат постановки в спулер; окон и диалогов не появляется, что обязательно для работы без присмотра.

**Alternatives considered**:
- **Ghostscript** (`gswin64c -dPrinted -dBatch -dNOPAUSE -dNumCopies=N -sDEVICE=mswinpr2 -sOutputFile="%printer%Имя"`) — умеет копии и выбор принтера, но управление дуплексом идёт через настройки драйвера/`DEVMODE`, а не флагом. Документирован как запасной бэкенд, если у конкретной модели SumatraPDF не отработает дуплекс.
- **Adobe Acrobat Reader CLI** (`/t`) — недокументированные ключи, показывает окна, ломается между версиями.
- **`win32print` RAW-печать** — требует, чтобы файл уже был на языке принтера (PS/PCL); для PDF означает собственный растеризатор. Избыточно.
- **`DEVMODE` через `win32print.DocumentProperties`** — позволяет выставить дуплекс/копии на уровне драйвера, но нужно рендерить страницы самим. Рассмотрен только как часть запасного пути.

**Проверка при приёмке**: обе стартовые модели (Pantum 5100, GM1033ADN) должны быть проверены на `duplexlong` вручную — маппинг «длинная/короткая кромка» у драйверов различается (задача приёмки в quickstart.md).

## R4. Обнаружение принтеров, их доступности и поддержки дуплекса

**Decision**: `pywin32`:
- список — `win32print.EnumPrinters(PRINTER_ENUM_LOCAL | PRINTER_ENUM_CONNECTIONS, None, 2)`;
- статус — `win32print.GetPrinter(handle, 2)` → поля `Status` (`PRINTER_STATUS_OFFLINE`, `PAPER_OUT`, `PAPER_JAM`, `NO_TONER`, `ERROR`, `PAUSED`) и `Attributes` (`PRINTER_ATTRIBUTE_WORK_OFFLINE`), `cJobs` — длина очереди;
- поддержка дуплекса — `win32print.DeviceCapabilities(name, port, DC_DUPLEX)` (1 = поддерживается).

**Rationale**: Закрывает FR-008 (предлагать дуплекс только там, где он есть), FR-015 (признак доступности в списке) и даёт человекочитаемые причины отказа для FR-017 без парсинга вывода утилит.

**Alternatives considered**: парсинг `wmic printer` / `Get-Printer` из PowerShell — медленнее (запуск процесса на каждую проверку), вывод локализован и его разбор хрупок. WMI через `pywin32`/`wmi` — тяжелее и требовательнее к правам.

**Замечание**: статус драйвера — не гарантия успеха печати (принтер может «молчать» об отсутствии бумаги). Поэтому статус задания «отправлено на принтер» формулируется в тексте бота честно, а конечный успех подтверждается уходом задания из очереди спулера.

## R5. Способ запуска на Windows-хосте

**Decision**: запуск в сессии конкретного пользователя через **Планировщик заданий**: триггер «При входе в систему», действие — `pythonw.exe -m printbot`, включены «Перезапускать при сбое» (каждую минуту, до 3 раз) и «Запускать вне зависимости от питания». Дополнительно — отключение спящего режима хоста.

**Rationale**: Сетевые принтеры (`\\сервер\принтер`) подключаются **на уровне пользователя** и не видны процессу, работающему под `LOCAL SYSTEM`. Служба под SYSTEM — самая частая причина «бот запустился, но принтеров нет». Планировщик в пользовательской сессии решает это без дополнительного ПО и даёт автозапуск и автоперезапуск (FR-029).

**Alternatives considered**:
- **NSSM / WinSW как служба** — работает круглосуточно без входа пользователя, но требует запуска от имени того же пользователя (иначе теряются принтеры) и хранения его пароля; оставлен как вариант, если понадобится печать без залогиненного пользователя.
- Ярлык в папке «Автозагрузка» — нет автоперезапуска при падении и нет контроля.
- Docker/WSL — принтеры Windows оттуда недоступны. Отклонено.

## R6. Хранилище состояния

**Decision**: SQLite (`aiosqlite`) с `journal_mode=WAL`, схема применяется миграциями на старте, доступ через тонкие репозитории с явным SQL.

**Rationale**: Один файл, ноль администрирования на офисном компьютере, транзакционность — этого достаточно для десятков пользователей и сотен заданий в месяц. Персистентность заданий обязательна для FR-019 (восстановление после перезапуска) и FR-027 (бессрочный журнал). WAL снимает блокировки между воркерами печати и хендлерами бота.

**Alternatives considered**: JSON/CSV-файлы — нет транзакций, гонки между воркерами; PostgreSQL/MySQL — лишний сервис на пользовательской машине; SQLAlchemy ORM — оправдана при сложной модели, здесь 4 таблицы и десяток запросов, явный SQL проще и легче тестируется.

## R7. Код доступа и защита от подбора

**Decision**: хранить только `scrypt`-хеш кода с солью (`hashlib.scrypt`, stdlib) в таблице `settings`; сверка через `hmac.compare_digest`. Блокировка: 5 неверных попыток подряд → блокировка ввода на 15 минут для этого `telegram_id` (FR-022), счётчики в БД. Сообщение с введённым кодом удаляется из чата сразу после проверки.

**Rationale**: Код — общий секрет офиса, попадает в историю чата и в логи, если не позаботиться; хеш + удаление сообщения минимизируют утечку. `scrypt` в stdlib избавляет от зависимости `passlib`/`argon2`. Блокировка в БД, а не в памяти — переживает перезапуск бота, иначе перебор обходится ожиданием рестарта.

**Alternatives considered**: хранить код в открытом виде в `.env` (просто, но утечка файла = утечка кода и невозможность отследить смену); ограничение частоты только в памяти (сбрасывается при перезапуске); одноразовые персональные приглашения (мощнее, но заказчик выбрал вариант с общим кодом).

## R8. Очередь заданий и параллелизм

**Decision**: на каждый принтер — своя `asyncio.Queue` и один воркер-таска; конвертация и печать выполняются как внешние процессы через `asyncio.create_subprocess_exec` с таймаутами; статусы задания меняются в БД и отправляются автору.

**Rationale**: Один воркер на принтер даёт последовательность заданий и исключает перемешивание страниц (FR-016, SC-010) без блокировок. Разные принтеры печатают параллельно. Внешние процессы через asyncio не блокируют цикл событий, поэтому бот продолжает отвечать другим пользователям (FR-018).

**Alternatives considered**: `ThreadPoolExecutor` с блокирующими вызовами — рабочий вариант, но смешивает две модели конкурентности; Celery/RQ — требуют брокера, несоразмерно задаче; печать прямо в хендлере — блокирует бота и нарушает FR-018.

**Восстановление после перезапуска (FR-019)**: на старте задания в статусах `QUEUED`/`CONVERTING`/`PRINTING` переводятся в `FAILED` с кодом `INTERRUPTED`, авторам уходит уведомление с предложением повторить. Автоматический повтор не делается сознательно: нельзя отличить «не напечаталось» от «напечаталось, но бот упал», а повтор стоит бумаги.

## R9. Валидация файла и подсчёт страниц

**Decision**: формат определяется по сигнатуре содержимого, а не по расширению:
- PDF — файл начинается с `%PDF-`; зашифрованность проверяется через `pypdf.PdfReader(...).is_encrypted`;
- DOCX — ZIP-сигнатура `PK\x03\x04` + наличие `[Content_Types].xml` и `word/document.xml` в архиве;
- сигнатура OLE (`D0 CF 11 E0`) = старый `.doc` или DOCX, защищённый паролем → понятный отказ (FR-005);
- всё прочее → отказ с перечислением поддерживаемых форматов (FR-003).

Число страниц берётся из готового PDF через `pypdf` — единообразно для обоих форматов; при превышении порога (по умолчанию 20 страниц) запрашивается дополнительное подтверждение.

**Rationale**: Расширению и MIME из Telegram доверять нельзя — файл можно переименовать; проверка содержимого закрывает FR-003/FR-005 честно. Подсчёт страниц после конвертации точен, тогда как оценка страниц DOCX без рендера принципиально неточна.

**Размер файла**: `message.document.file_size` проверяется **до** скачивания; предел — 20 МБ (ограничение `getFile` в Bot API для ботов), дублируется собственной настройкой (FR-004).

## R10. Временные файлы и их гарантированное удаление

**Decision**: каталог на задание `%LOCALAPPDATA%\printbot\jobs\<job_id>\`, удаление в `finally` при любом исходе; при старте — подметание каталогов старше 1 часа; периодическая задача очистки раз в 10 минут.

**Rationale**: Три независимых механизма дают выполнение FR-028/SC-007 даже при падении процесса посреди задания. Отдельный каталог на задание исключает коллизии имён при одинаковых именах файлов у разных пользователей.

## R11. Тестирование без принтера

**Decision**: `PrinterBackend` и `DocumentConverter` — `typing.Protocol`; в тестах используются `FakePrinterBackend` (пишет «напечатанное» в каталог и умеет по команде возвращать ошибки `OFFLINE`, `PAPER_OUT`, `TIMEOUT`) и `FakeConverter`. Контрактные тесты проверяют, что и реальная, и фейковая реализации соблюдают один и тот же интерфейс и таксономию ошибок. `pytest` + `pytest-asyncio`; интеграционные тесты гоняют полный путь «документ → параметры → очередь → результат» на фейках.

**Rationale**: Позволяет разрабатывать и проверять почти весь функционал на любой машине (в т.ч. Linux), оставляя ручной проверке на хосте только два модуля — реальную печать и конвертацию (см. quickstart.md).

## Сводка решений

| Область | Решение |
|---|---|
| Бот | aiogram 3.x, long polling, FSM + middleware авторизации |
| DOCX→PDF | LibreOffice headless с изолированным профилем на запуск |
| Печать | SumatraPDF CLI (`-print-to`, `-print-settings`), запасной путь — Ghostscript |
| Принтеры | pywin32: `EnumPrinters`, `GetPrinter(level 2)`, `DeviceCapabilities(DC_DUPLEX)` |
| Запуск | Планировщик заданий в пользовательской сессии, перезапуск при сбое |
| Хранилище | SQLite (aiosqlite, WAL), явный SQL, миграции при старте |
| Доступ | scrypt-хеш общего кода, блокировка 5 попыток / 15 минут, счётчики в БД |
| Очередь | asyncio.Queue + один воркер на принтер, внешние процессы через asyncio |
| Валидация | Проверка сигнатур файла, число страниц из PDF через pypdf |
| Тесты | pytest + pytest-asyncio, фейковые бэкенды печати и конвертации |

# Quickstart — развёртывание и приёмочная проверка

**Дата**: 2026-09-08 | Спека: [spec.md](./spec.md) | План: [plan.md](./plan.md) | Контракты: [contracts/](./contracts/)

Документ отвечает на два вопроса: как поднять бота на офисном компьютере и как убедиться, что фича действительно работает. Детали интерфейсов не дублируются — см. contracts/.

---

## 1. Предварительные требования (хост Windows)

| Компонент | Проверка |
|---|---|
| Windows 10/11 x64, учётная запись, под которой подключены принтеры | `whoami` |
| Python 3.12 | `python --version` |
| LibreOffice | `"C:\Program Files\LibreOffice\program\soffice.exe" --version` |
| SumatraPDF (portable) в `tools\SumatraPDF.exe` | файл существует |
| Оба принтера установлены и печатают тестовую страницу из Windows | «Параметры → Принтеры» |
| Токен бота от @BotFather | получен |
| Свой Telegram ID | у @userinfobot |

Отключить спящий режим хоста: **Параметры → Питание → Сон: Никогда**.

## 2. Установка

```powershell
git clone <repo> C:\printbot
cd C:\printbot
python -m venv .venv
.venv\Scripts\pip install -e ".[dev]"
copy .env.example .env
copy printers.example.toml printers.toml
```

Заполнить `.env` (`BOT_TOKEN`, `ADMIN_IDS`) и `printers.toml` (`system_name` — точные имена из списка принтеров Windows). Схема обоих файлов: [contracts/configuration.md](./contracts/configuration.md).

Точные имена принтеров:

```powershell
.venv\Scripts\python -m printbot.tools.list_printers   # либо: Get-Printer | Select-Object Name
```

## 3. Первый запуск

```powershell
.venv\Scripts\python -m printbot
```

Ожидается: в консоли один раз печатается сгенерированный код доступа (дальше хранится только его хеш), выводится список найденных принтеров с признаком поддержки дуплекса, бот переходит в режим приёма сообщений.

## 4. Автозапуск (Планировщик заданий)

```powershell
schtasks /Create /TN "PrintBot" /TR "C:\printbot\.venv\Scripts\pythonw.exe -m printbot" /SC ONLOGON /RL LIMITED /F
```

Затем в «Планировщике заданий» у задачи `PrintBot` включить: **Перезапускать при сбое** — каждую 1 минуту, до 3 раз; снять «Останавливать при переходе на батарею». Обоснование выбора пользовательской сессии вместо службы — [research.md R5](./research.md).

## 5. Автоматические проверки (можно запускать на любой машине)

```powershell
.venv\Scripts\pytest tests/unit tests/contract -q      # логика, валидация, контракты бэкендов
.venv\Scripts\pytest tests/integration -q              # сквозной путь на фейковом принтере
.venv\Scripts\pytest -q                                # всё сразу
```

Интеграционные тесты работают с `PRINT_BACKEND=fake` и фейковым конвертером — принтер и LibreOffice не нужны.

## 6. Приёмочные сценарии (вручную, на хосте)

Каждый пункт соответствует пользовательской истории и критерию успеха из спеки.

### 6.1 Базовая печать DOCX — US1, SC-001, SC-004
1. Отправить боту `/start`, ввести код доступа.
2. Отправить DOCX на 2 страницы → выбрать принтер → «односторонняя» → 1 копия → подтвердить.
3. **Ожидается**: бот отвечает подтверждением с номером задания; документ выходит на выбранном принтере; весь путь занял < 60 секунд и не более 4 шагов после авторизации.

### 6.2 Двусторонняя печать и копии — US1, FR-006, FR-007
Отправить тот же файл, выбрать «двусторонняя» и 3 копии.
**Ожидается**: 3 экземпляра, печать на обеих сторонах, длинная кромка. Проверить на **обеих** моделях — маппинг `duplexlong`/`duplexshort` у драйверов различается ([research.md R3](./research.md)).

### 6.3 Печать PDF — US1 сценарий 3, FR-002
Отправить PDF на 3 страницы. **Ожидается**: те же шаги диалога, корректный результат.

### 6.4 Выбор принтера — US2, SC-008
1. При двух включённых принтерах отправить файл → в списке оба, с признаком доступности.
2. Выключить один физически → отправить файл → он помечен недоступным и не выбирается (FR-015).
3. Оставить в `printers.toml` один принтер, перезапустить → шаг выбора пропускается (US2 сценарий 2).

### 6.5 Доступ по коду — US3, SC-006
1. С другого аккаунта отправить файл → печать не запускается, запрошен код.
2. Ввести неверный код 5 раз → ввод блокируется на 15 минут (FR-022).
3. Ввести верный код → доступ выдан, при следующем файле код не запрашивается.
4. `/setcode`, задать новый → старый код новому пользователю не подходит, ранее авторизованный продолжает печатать (FR-023).
5. `/revoke <id>` → у отозванного задание отклоняется (FR-024).

### 6.6 Отказы и понятные причины — US4, SC-005
| Действие | Ожидаемая реакция |
|---|---|
| Отправить `.xlsx` | Отказ + перечень поддерживаемых форматов |
| Отправить файл > 20 МБ | Отказ до скачивания, указан предел |
| Отправить PDF с паролем | Отказ: файл защищён паролем |
| Выключить принтер и подтвердить задание | Сообщение о недоступности принтера, предложение выбрать другой |
| Вынуть бумагу и напечатать | Сообщение про бумагу, задание завершается с ошибкой, а не «зависает» |
| Ввести «пять» вместо числа копий | Подсказка о допустимом диапазоне 1…50 |

### 6.7 Очередь и параллелизм — SC-010
С трёх аккаунтов одновременно отправить по заданию на один принтер.
**Ожидается**: все три печатаются полностью, страницы разных документов не перемешаны, каждый получает статус только по своему заданию.

### 6.8 Восстановление после перезапуска — FR-019
Поставить задание в очередь и убить процесс бота. Запустить снова.
**Ожидается**: задание помечено `FAILED` с причиной «прервано», автор получил уведомление с предложением повторить; бот работает.

### 6.9 Удаление временных файлов — FR-028, SC-007
После серии заданий проверить `%LOCALAPPDATA%\printbot\jobs`.
**Ожидается**: каталог пуст (или очищается в течение 10 минут); документов пользователей на диске не остаётся.

### 6.10 Журнал администратора — US5, SC-011
`/journal 20` от администратора.
**Ожидается**: перечислены проведённые задания с автором, файлом, параметрами, принтером, временем и результатом; та же команда от обычного пользователя отклоняется.

## 7. Диагностика

| Симптом | Причина и что делать |
|---|---|
| Бот не видит принтеров | Процесс запущен не под тем пользователем (служба под SYSTEM не видит сетевые принтеры) — [research.md R5](./research.md) |
| DOCX не конвертируется, ошибка таймаута | Запущенный экземпляр LibreOffice; проверить, что используется отдельный `-env:UserInstallation` на вызов |
| Печатает односторонне при выборе «двусторонняя» | Проверить `duplexlong` / `duplexshort` для конкретной модели; при неудаче переключить `PRINT_BACKEND=ghostscript` |
| Вёрстка DOCX «поехала» | Отсутствуют шрифты документа — установить их на хост |
| Бот молчит после разрыва сети | Проверить логи и перезапуск задачи в Планировщике |

Логи: `logs/printbot.log` (ротация). Секреты и коды доступа в логи не пишутся.

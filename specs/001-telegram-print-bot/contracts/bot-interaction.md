# Contract: интерфейс бота (команды, состояния, callback-данные)

**Дата**: 2026-09-08 | Тип интерфейса: диалог в Telegram — единственная точка контакта с пользователем.
Все тексты — на русском ([texts.py](../plan.md)); ниже приведены смысловые формулировки, а не дословные строки.

## Команды

| Команда | Кто может | Поведение | Требование |
|---|---|---|---|
| `/start` | все | Приветствие, краткая инструкция. Неавторизованному — запрос кода доступа | FR-021 |
| `/help` | авторизованные | Поддерживаемые форматы, лимит размера, диапазон копий, как отменить | FR-003 |
| `/cancel` | авторизованные | Отмена оформляемого задания, очистка FSM и временных файлов | FR-010 |
| `/status` | авторизованные | Последние 5 заданий пользователя с их статусами | FR-017 |
| `/printers` | авторизованные | Список принтеров с признаком доступности | FR-015 |
| `/journal [N]` | только ADMIN | Последние N (по умолчанию 20) заданий: автор, файл, параметры, принтер, время, результат | FR-026, SC-011 |
| `/setcode` | только ADMIN | Диалог смены кода доступа; сообщение с новым кодом удаляется из чата | FR-023 |
| `/revoke <telegram_id>` | только ADMIN | Отзыв доступа у пользователя | FR-024 |
| `/users` | только ADMIN | Список авторизованных пользователей | FR-025 |

Команды администратора для не-администратора отвечают отказом и не раскрывают их существование в `/help` (FR-025).

## Приём файла

| Вход | Реакция |
|---|---|
| Документ DOCX или PDF, размер ≤ лимита, пользователь `ALLOWED` | Начало диалога оформления (см. FSM) |
| Документ другого формата | Отказ + перечисление поддерживаемых форматов (FR-003) |
| Документ с `file_size` > лимита | Отказ **до** скачивания + указание предела (FR-004) |
| Повреждённый / пустой / зашифрованный файл | Отказ с указанием причины (FR-005) |
| Фото/сжатое медиа вместо документа | Подсказка отправить файл «как документ» |
| Несколько файлов одним сообщением | Обработка по одному, с явным указанием, какое задание оформляется |
| Файл от пользователя `PENDING`/`REVOKED` | Файл не скачивается, запрос кода доступа (FR-020) |
| Новый файл во время незавершённого диалога | Старый черновик отменяется с явным сообщением, начинается новый (US1 сценарий 4) |

## Конечный автомат диалога (FSM)

```text
[нет состояния]
   │ документ принят и провалидирован
   ▼
choosing_printer ──(принтеров ровно 1: шаг пропускается)──┐
   │ callback pr:<key>                                    │
   ▼                                                      ▼
choosing_duplex  ◄────────────────────────────────────────┘
   │ callback dx:<simplex|duplex>   (кнопка «двусторонняя» отсутствует, если принтер её не умеет — FR-008)
   ▼
entering_copies
   │ callback cp:<1|2|5> либо текстом число 1..50 (FR-007)
   ▼
confirming  ── callback ok:go ──> задание создано (QUEUED) ──> [нет состояния]
   │
   └── callback ok:cancel, /cancel, таймаут 15 мин ──> отмена, файл удалён (FR-010, FR-011)
```

Дополнительный шаг: если `page_count > LARGE_DOC_PAGES` (по умолчанию 20), между `confirming` и постановкой в очередь запрашивается отдельное подтверждение объёма.

Состояние `AuthFlow.waiting_code` — независимая ветка: любое сообщение неавторизованного пользователя ведёт в неё (FR-021).

## Схема `callback_data`

Формат: `<префикс>:<значение>`, длина ≤ 64 байт (ограничение Telegram).

| Префикс | Значение | Смысл |
|---|---|---|
| `pr` | ключ принтера из конфига | Выбор принтера |
| `dx` | `simplex` \| `duplex` | Режим сторон |
| `cp` | целое 1…50 | Быстрый выбор числа копий |
| `ok` | `go` \| `cancel` | Подтверждение / отмена задания |
| `big` | `go` \| `cancel` | Подтверждение печати объёмного документа |
| `adm` | `journal` \| `users` \| `setcode` | Действия администратора |

Устаревший callback (нажатие на кнопку старого сообщения после сброса состояния) отвечает подсказкой «задание уже неактуально, отправьте файл заново» и не создаёт задание.

## Сообщения о статусе задания

Автору задания уходят уведомления при смене статуса (FR-017); чужие статусы не показываются (US4 сценарий 4).

| Событие | Содержание сообщения |
|---|---|
| Задание принято (`QUEUED`) | Номер задания, имя файла, принтер, режим сторон, копии, позиция в очереди |
| Отправлено на принтер (`DONE`) | Подтверждение с номером задания |
| Ошибка (`FAILED`) | Причина простым языком по `ErrorCode` + что делать дальше |
| Прерывание при перезапуске (`INTERRUPTED`) | Сообщение, что задание не завершено, с предложением повторить (FR-019) |

Таблица соответствия `ErrorCode` → текст для пользователя ведётся в `texts.py`; технические детали (`error_detail`) в чат не попадают (FR-017).

## Инварианты интерфейса

1. Ни одно действие, приводящее к расходу бумаги, не выполняется без явного подтверждения (FR-009).
2. Ни один запрос от неавторизованного пользователя не приводит к скачиванию файла или печати (FR-020).
3. Любое отклонённое действие сопровождается причиной и подсказкой, что делать.
4. Каждое подтверждённое задание получает ровно один финальный статус (FR-017).
5. Введённый код доступа удаляется из чата и не попадает в логи (research.md R7).
